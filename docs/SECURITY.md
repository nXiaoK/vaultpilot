# 安全边界

业务数据、目录与文件名由 Restic 加密。云端全局恢复清单及仓库登记采用认证加密；云盘账号泄露不能直接读业务明文，但仍可能删除云端数据，大小与访问模式等信息也可能暴露。

主密钥为随机 256 位密钥，使用 Argon2id 派生密钥和 AES-256-GCM 保护；每个仓库独立随机密码。管理员密码使用单独加盐的 Argon2id 哈希。OAuth Token 用节点密钥认证加密存储，节点密钥文件必须为 0600。恢复包不包含 OAuth Token。运行中的服务器或宿主机高权限被攻破不在抵御范围内；自动解锁尤其依赖宿主机安全。

多节点连接需要写入节点明确发布 `connect.vpkey`，复用原备份密码保护随机主密钥；不会从密码确定性生成主密钥或库 ID。入口可被离线猜测密码，应使用强密码。连接必须匹配路径、外层与加密载荷的库 ID；最大 64 KiB，严格校验版本和 KDF，限速密码尝试，限制读取与子进程总输出。连接密码不写入任务、日志或浏览器持久存储。每个恢复节点保留独立管理员与账号令牌，待连接节点不创建临时备份库。恢复账号验证只检查读取访问，实际 Restic 操作仍可能使用引擎锁，不构成 OAuth 只读隔离。

浏览器使用 HttpOnly / SameSite 会话 Cookie，写请求使用 CSRF token，登录限速并有会话过期。公网必须使用 HTTPS 和正确的 VP_PUBLIC_URL。默认 compose 仅绑定回环网络；需要通过配置好的反向代理访问，不要直接公开 8080。

所有 API 和静态页面先校验 Host，阻止恶意域名通过 DNS rebinding 初始化或读取实例。默认允许回环主机；其他入口只接受 `VP_PUBLIC_URL` 的完整 Host（含端口）和 `VP_ALLOWED_HOSTS` 明确列出的 Host。不要把不受信任的域名加入允许列表。未登录的 `/api/status` 只返回初始化与登录状态，库标识、部署路径、密钥状态及引擎配置仅登录后提供。

认证尝试按操作与客户端 IP 分桶，15 分钟内最多 10 次，成功验证清零对应计数。`VP_TRUSTED_PROXIES` 默认为空，忽略客户端伪造的 `X-Forwarded-For`；配置后仅信任来自这些 CIDR 的代理，并从转发链右侧定位首个非可信客户端。可信代理须正确维护转发链；错误配置可能导致多人共用计数或允许伪造来源。

Argon2id 派生共用两个并发槽位，最多同时执行两次 64 MiB 派生，KDF 参数与密文格式保持一致。登录、解锁、登出、恢复包与账号包导出、云端密码接口请求体限制 8 KiB；首次设置含恢复包的请求限制 1 MiB。其他平台 JSON 请求默认仍为 16 MiB，账号包导入保留 2 MiB 上限。

程序通过参数数组调用引擎，不接收任意 shell 或引擎命令。引擎子进程仅继承路径、用户、临时目录、时区、语言、证书及 HTTP 代理白名单环境变量，宿主的引擎设置和 VaultPilot 密钥不会自动传入。备份源仅来自部署授权目录，并校验实际目录、挂载身份和读取权限。链接保存本身，扫描不跟随链接；恢复目标独立授权、无默认覆盖，所有结果路径必须受目标根目录约束。

只读挂载备份源、非 root、只读容器根目录、去除 capabilities、不挂 Docker Socket、不使用 privileged。UID/GID 应按真实源文件权限配置。恢复、维护可能需要引擎锁操作，recovery 模式属于应用写入限制，不能称为 OAuth 云端只读隔离。

普通目录备份是运行区间内尽力一致性，不是跨仓库原子快照。活跃数据库需要应用导出或一致性文件系统快照；请不要把普通文件复制成功当成数据库可恢复保证。

## Rclone 授权与导入

Rclone 标准授权由实际子进程执行，使用官方共享应用。其标准授权码流程由 Rclone 实现，不宣称带有自定义网页流程的 PKCE。平台另行绑定登录会话、账号版本、10 分钟期限及 Rclone state。远程回调粘贴只接受 `http://localhost:53682/` 或 `http://127.0.0.1:53682/` 的本次授权地址；请求目标始终由服务器构造为自身 loopback，禁止跟随重定向，粘贴地址不能成为任意服务请求。取消、登出及关闭服务会终止所属授权子进程。

导入接口不保存整份文件，按 provider 的允许字段重建 OneDrive 或 Google Drive 配置；仅接受各 provider 支持的官方授权/令牌端点，不接受客户端凭据模式、其他云区域或不支持的企业/共享 Drive。刷新令牌、自定义应用设置和授权版本一同认证加密，列表、预览和状态响应不包含它们。Rclone 的 obscure 只是可逆编码，导入后仍需节点密钥保护。临时配置权限 0600，子进程输出不写入任务日志，过滤宿主 `RCLONE_*` 环境覆盖。授权版本检查防止旧任务的刷新令牌覆盖新授权。

配置和完整回调地址均是敏感数据。仅在可信 HTTPS 或本机页面传入；反向代理不要记录请求体，回调粘贴请求本身不把授权码写入 API URL。恢复包仍不包含账号凭据，异机恢复需要重新授权或导入账号。

## 账号包凭据迁移

独立的 `vaultpilot-accounts` 包以 Argon2id（3 次、64 MiB、并行度 2）派生密钥，AES-GCM 的 AAD 为 `vaultpilot-accounts-v1`，与恢复包域隔离。盐随机 16 字节，nonce 由加密函数随机生成。解密前拒绝未知格式/版本/KDF 参数及超限内容；校验后端与凭据 provider 一致、凭据模式、Microsoft 租户或 Google scope 白名单、稳定 Drive ID 和可移植预算设置，阻止 Rclone 配置行注入。密钥和明文临时字节缓冲在使用后清零；API 日志/审计只记录操作和资源，不记录密码、Token 或应用密钥。

导出恢复包或账号包必须再次提供当前管理员登录密码，仅有会话 Cookie 与 CSRF 不足以导出。重新认证失败按 `reauth` 操作与客户端 IP 限速，成功验证清零该计数；此密码不进入导出包、审计或浏览器持久存储。

包中的 Rclone obscure 客户端密钥保持原编码，custom OAuth 密钥保持明文语义但只存放在加密负载中，接收节点用自己的本地密钥重新加密。原应用设置优先于接收节点全局 OAuth 配置。导出/导入都需要管理员会话与 CSRF，界面明确提示共享原授权权限；导入不会把导出节点的已验证状态直接视为本地可信。

## Google Drive 权限与删除

Google 标准授权和导入固定 `scope = drive`，即 `https://www.googleapis.com/auth/drive`，允许整个 Google Drive 的读写。应用层将备份路径限定为 `VaultPilot/<vault_id>`，这不等于 OAuth 权限被云端限定在该文件夹。恢复节点的只读限制也不改变 Token 本身的权限。未采用 `drive.file`，因为它限制跨 client 可见性，换应用可能使原备份目录不可见并创建同名目录。

Google 凭据仅允许 Rclone 模式。Google 授权 URL 严格绑定官方主机/路径、Drive scope、offline/code、loopback redirect、client ID 和本次 state，标准授权追加 `prompt=consent select_account`。配置拒绝 Shared Drives、服务账号、impersonate、环境认证与非默认授权端点等可能改变身份或访问边界的设置。

所有生成的 Google remote 固定 `use_trash = false`：prune、历史清理、迁移后旧副本清理与清空为永久删除，不进入回收站，无法从 Google 回收站找回。其他工具和 Google 网页的删除设置不会因此改变。共享存储组只是容量防重措施，不提供权限隔离。自建 Google client 仅通过已有 Rclone 配置导入，其 secret 仍和 Token 一起认证加密；obscure 本身不是加密保护。
