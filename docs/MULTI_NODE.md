# 多节点密码连接

支持一个 A 备份写入节点和多个 B/C 恢复节点。A 发布备份到 OneDrive，B/C 用原备份密码连接同一备份库，自动发现恢复点，再按需下载到本地。普通接入不需要传递恢复包；每个节点仍需独立授权原 OneDrive 账号。

## 已有 A 节点开启连接

1. 升级并重新构建/部署本版本，保留 A 原有 `state` 和账号配置。
2. 登录后先用原备份密码解锁 A，确认原备份账号已启用、验证成功，并已有完整恢复点。
3. 在「安全与维护 → 多节点密码连接」输入**创建备份库时设置的备份库保护密码**，勾选云端连接资料发布确认，点击「启用并发布密码连接」。这不是管理员登录密码，也不是后来独立导出恢复包时设置的密码。
4. 确认至少一个账号发布并读回校验成功；其他账号失败时修复后重新发布。后续目录提交会向参与提交的账号同步此入口。

开启连接不会重新初始化已有仓库，不改变原库身份、主密钥或密码。同样的密码分别用于创建两个新库时，仍得到两个独立随机身份的库。

## B 节点接入

1. 部署相同或兼容版本，为 B 准备**独立全新状态目录**和可写恢复目录，例如 `.env` 设置 `VP_RESTORE_HOST=/data/from-a`。不复制 A 正在使用的数据库。
2. 首次页面选择「从云端连接」，仅设置本节点管理员账号和登录密码。登录密码必须与 A 的备份密码不同。此时还未创建或解锁任何备份库，允许先授权账号。
3. 在「存储账号」通过 Rclone 标准授权或配置导入接入 A 使用的原账号，显式选择原 Drive，完成读取访问验证。分布在两个 OneDrive 的数据需要接入两个账号才能完整恢复。
4. 打开「安全与维护 → 连接已有云端备份库」，点击「查找云端备份库」。显式选择与 A 界面中库标识一致的库，输入 **A 的原备份密码**，点击「连接并建立恢复节点」。
5. 连接成功后自动提交一次云端发现，并默认开启每分钟检查。查看「最近检查」「最近发现成功」和任务报告；在「恢复中心」选择恢复点、范围和目标，预检查后开始恢复。

Compose 中目标 `/restore/from-a` 对应宿主机 `/data/from-a/from-a`。「恢复目录布局」默认自动判断实际所选范围：只包含一个备份源时直接输出原相对路径，例如 `/data/from-a/from-a/photos/2026.jpg`；多个备份源时增加各自的 `<备份源ID>/` 子目录。需要保留旧布局时选择「按备份源 ID 分目录」；「直接恢复到目标目录」仅允许单源。预检查与任务报告显示实际输出目录，冲突列表显示对应目标路径。恢复约 1.6 TB 数据时，本地需要足够的可用容量，并为缓存和最大单文件暂存留出余量。

已有实例不能切换或覆盖到另一备份库。若 B 已初始化为其他库，使用另一个独立状态目录建立恢复实例。已经通过恢复包连接的恢复节点可直接在新界面开启自动发现，无需重新连接。

## 自动发现的范围

- 检查由服务端执行，关闭浏览器后继续运行；服务停止或节点锁定时暂停。重启后使用相同备份密码解锁，或按部署配置使用受限自动解锁文件。
- 每分钟列举小型云端完成证书目录；目录或账号映射变化后才排队发现。重复证书复用之前已经认证的控制登记，不重复下载完整目录；新提交复用旧恢复点文件索引。
- 新索引完成验证后事务发布；失败保留已有恢复点。实际恢复与发现重建互斥，长时间恢复可能推迟新点出现在列表中。
- 自动发现更新恢复点列表，**不会自动恢复文件、删除 B 的额外文件或进行双向同步**。文件恢复需要选择范围和目标；覆盖已有文件需明确允许。
- B/C 在应用层禁止备份、云端保护状态修改、历史清理和迁移。当前没有跨节点写入租约，不支持把 B/C 同时作为此库的备份写入节点。

## 云端连接资料

入口为 `VaultPilot/<vault_id>/connect.vpkey`。它只包含由原备份密码以 Argon2id + AES-GCM 保护的解锁资料，不包含明文备份密码、明文主密钥或 OneDrive Token。连接验证绑定目录、外层与加密内容的库 ID，未知版本、篡改和错误密码被拒绝。输入和子进程输出有大小限制，密码验证有限速。

开启后，取得入口副本的人可以尝试离线猜测备份密码，因此应使用强密码。仍建议离线保留恢复包，云端入口被删除或账号无法访问时可使用原有恢复流程；该备用资料不是日常节点连接的必需输入。

真实引擎测试覆盖独立状态 A → 共享本地存储入口 → B 的密码接入、新点自动发现和恢复内容核对。该入口不是 OneDrive；真实 OneDrive Personal 跨机器演练仍需要在实际账号上执行。
