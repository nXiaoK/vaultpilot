# VaultPilot 架构决策（V1）

本项目遵循《多账号 OneDrive 加密备份平台.md》。Go 管理服务、Vue 3 + TypeScript、SQLite、Restic、Rclone，单容器部署。一个 Restic 仓库只属于一个 Drive；文件集合是分片单位，不拆 Restic 内部数据块。多个账号用于容量分摊，不是业务数据多副本。

## 数据与容量

SQLite 使用 WAL，实体分表、乐观版本检查；文件清单与稳定归属使用独立索引表，扫描批量写入。历史恢复点拥有独立文件清单和完整快照 ID。已经删除的文件不会借用旧快照重新出现。容量使用整数 Bytes，配额缺失或过期时禁止分配；事务内计算所有未结算预留，避免并发超卖。初次备份按原始大小加保守开销估算，不依赖压缩。

## 密钥与异机恢复

管理员密码只用于网页登录。随机主密钥使用 Argon2id 派生的密钥及 AES-256-GCM 封装；每个仓库生成独立随机密码并封装在加密登记中。业务加密完全由 Restic 执行。OAuth 凭据用权限为 0600 的节点密钥加密存储，恢复包不携带 OAuth Token。

恢复包携带受保护的主密钥、vault ID、协议版本和发现入口。重新授权并匹配 Drive 稳定 ID 后，从每个 Drive 的 `VaultPilot/<vault_id>/catalog/` 读取版本化加密目录。先取得解锁能力，再读取仓库登记，避免循环依赖。每次提交生成不可变清单并读回验证，达到所配置的不同 Drive 副本数才发布完整恢复点；默认两份。

多节点也可通过云端密码连接接入：A 显式发布由原备份密码保护的 `connect.vpkey`，B 在独立状态目录中仅初始化管理员，再授权原 Drive、选择 A 的库并验证密码，原子建立恢复节点。每分钟检查云端提交目录，在变化时发现恢复点；发现与恢复互斥，索引验证后事务发布。此方式不需要手动传递恢复包，仍要求一个写入节点和多个恢复节点。详见 [多节点密码连接](MULTI_NODE.md)。

## 执行与安全

任务异步且状态持久化，按计划合并触发，重启标记中断。进程调用只传参数数组，取消进程组。源范围由部署提供的只读挂载决定；恢复目标由独立可写挂载决定。目录的符号链接不跟随，恢复在私有临时子目录进行并检查每个输出路径，禁止链接越界及默认覆盖。

同一实例持有排他节点锁；同一仓库的备份、恢复、检查、清理和迁移互斥。引擎自己的锁保留，禁止自动强制解锁。恢复节点关闭所有写入维护及定时备份。恢复的锁写入不等于 OAuth 只读隔离。

## 发布门槛

本地 Restic 闭环与真实 OneDrive 验证分别记录。必须在没有原始数据库及节点密钥的新状态目录中，以恢复包或云端密码连接及重新接入的存储恢复文件并核对内容。无真实微软配置时，T01/T02 及云端故障测试记为未验证，不能冒充正式发布。TB 级与百万文件属于待测性能目标。
