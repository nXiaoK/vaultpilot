# 当前实现与已知限制

本文件依据需求 V1.0、当前源码与已提供的测试结果整理。VaultPilot 已实现可操作的中文界面、Go API、真实 Restic/Rclone 编排及离线恢复协议，但尚未完成需求规定的真实 OneDrive 发布验收。界面可用、编译通过、本地真实引擎闭环和云端验收应分别判断。

## 验证范围

| 范围 | 当前结论 |
|---|---|
| Vue / TypeScript 产品界面 | 已构建；请求真实 API，不使用演示业务数据或假进度。 |
| Telegram 通知 | 支持节点独立配置、备份最终结果、授权异常去重及定期检查、持久化发送与重试；模拟 Telegram/Graph 和本地真实 Restic 测试通过，尚未使用真实 Bot 验证用户收到消息。采用至少一次投递，网络响应丢失时可能重复。详见 [通知指南](TELEGRAM.md)。 |
| 本地真实 Restic/Rclone 备份与恢复 | 已执行本地目录存储入口的闭环，包括历史版本、空白状态目录发现与内容核对。该入口不是 OneDrive。具体用例与结果以测试报告为准。 |
| OAuth、Drive 选择、刷新及错误处理 | 已实现；部分分支有模拟 HTTP 单元测试。支持自定义应用、Rclone 标准授权及配置导入。已测试真实 Rclone 授权进程启动/取消；未使用真实微软账号完成登录、读写和刷新，不能据此宣称 OneDrive 联调通过。 |
| 真实 OneDrive Personal | 尚未验证，包括两个真实账号的授权、配额、云端加密备份、限流、凭据刷新重启持久化及新服务器恢复。 |
| OneDrive 企业版 / SharePoint | 未验证，当前 Drive 验证流程拒绝非 Personal 类型；不能称为已支持。 |
| 10 个真实云端账号、5 TB 实际备份 | 未执行。没有实际云端吞吐、下载流量、限流与多 TB 恢复耗时结论。 |
| 100 万条索引 | 已测试合成 SQLite 文件索引的插入与分页查询。逻辑大小与十个合成仓库标识不代表扫描、备份或恢复了对应实体文件、5 TB 数据或十个 OneDrive。 |
| Docker / Debian 实际部署 | 已在 Debian 12.12 Linux arm64 容器完成镜像构建与冒烟，验证非 root、只读根文件系统、tmpfs、只读源绑定挂载，以及 API 初始化、登录、浏览与健康检查。证据见 [Docker 报告](evidence/docker-report.json)。用户目标 Debian 主机的完整备份/恢复演练仍未验证。 |

最重要的剩余发布门槛：在全新服务器、全新状态目录中，仅使用离线恢复包和重新授权的真实 OneDrive 完成恢复，并核对内容。原服务器状态、本地缓存和数据库不得参与此验收。可复现步骤见 [验收计划](ACCEPTANCE.md) 与 [恢复手册](RECOVERY.md)。

## 单写入节点与云端保护

- 同一状态目录使用本地排他文件锁，进程内按计划、账号和仓库加锁，并保留 Restic 引擎锁。当前没有跨服务器的云端写入租约、分布式 fencing 或主节点切换协议。同一个恢复包不能在两台服务器同时建立活跃写入节点；不同状态目录的本地锁不能阻止这种情况。
- 多账号提供容量分摊。每个业务分片仓库只放在一个 Drive，默认两个副本用于加密控制资料，并不是业务数据第二副本。某个业务仓库被删除或对应账号永久丢失时，控制资料副本不能补回其业务内容。
- 支持一个写入节点和多个密码接入恢复节点，需由写入节点明确发布加密连接入口；相同密码分别新建的库不会自动合并。恢复节点在应用层禁止备份、历史清理及迁移，仍需要账号访问与引擎锁操作。OAuth 权限不构成云端只读隔离。
- 加密保护云端内容与目录清单的机密性，不能阻止云端删除，也不能抵御已取得运行服务器高权限和解密资料的攻击者。自动解锁依赖外部 Secret 与宿主机权限保护。
- 当前没有网页主密钥轮换、恢复格式迁移或活跃写入节点切换功能。导出时重新设置包保护密码仅保护此次恢复包，不轮换库主密钥或当前节点的解锁密码。发现入口将失效前应重新导出并验证恢复资料。

## 文件与一致性兼容性

| 类型 / 元数据 | 当前行为与边界 |
|---|---|
| 普通文件 | 支持加密备份及按历史清单恢复内容；最终目标还原文件大小、普通权限位和修改时间。 |
| 目录及空目录 | 支持；恢复后应用普通权限位与修改时间。 |
| 中文、空格、换行及特殊字符名称 | 使用 NUL 文件清单与 JSON 索引，不按业务路径的换行拆分。已测范围仍以具体测试用例为准。 |
| 非 UTF-8 文件名或符号链接目标 | 明确拒绝并返回 UNSUPPORTED_FILENAME_ENCODING，避免 JSON 替换字符损坏恢复映射；不能表示为完整成功。 |
| 符号链接 | 备份链接本身，不跟随目标；恢复拒绝绝对目标和超出源逻辑边界的链接。此安全策略意味着某些原有外部链接可以被备份，但不能按原样恢复。链接所有者与链接时间不完整还原。 |
| 硬链接 | 文件内容可作为普通文件恢复，不保留多个路径共享同一 inode 的硬链接身份。 |
| UID/GID、ACL、扩展属性、特殊权限位 | 最终恢复层没有完整还原 UID/GID、ACL、xattr、setuid/setgid/sticky 等元数据；不能作为全保真系统迁移工具。 |
| 设备、FIFO、Socket 等特殊文件 | 扫描明确失败，不静默纳入完整成功。 |
| 活跃数据库与正在写入的数据 | 普通目录备份是执行区间内的尽力一致性。类型、大小和修改时间的变化会检查，但不是原子文件系统快照，也不是应用事务一致性；需要预先应用导出或外部一致性快照。 |

隐藏文件、排除模式、跨文件系统边界和单文件大小上限属于用户配置的范围。超过大小上限的文件不纳入源，目前没有完整的逐项排除清单。恢复后的顶层路径按稳定 `source_id` 组织；不会自动还原原主机的绝对路径或挂载布局。

## 恢复流程与报告

- 默认冲突策略为预检查阻塞，要求用户改用新目录或明确允许覆盖；目前没有“自动跳过全部冲突并继续”的独立策略。目录与非目录类型冲突可能即使允许覆盖也被拒绝。
- 预检查返回总冲突数与缺失文件数，条目示例各最多 200 项，避免一次返回全部目录。示例不是完整导出的逐文件清单。
- 恢复按批次在受控暂存目录解密再复制到目标，需要额外工作空间。一般批次以 64 MiB 作为参考，单个更大文件仍需要相应暂存空间；没有要求暂存整个云端仓库。
- 预检查核对当前缓存占用与预计临时片段，单个文件或所选批次需要的工作空间超过缓存预算时明确阻止恢复；增加源数据规模不代表可以忽略最大单文件的暂存需求。
- 成功、明确的部分恢复与预检查通过后的中途失败均保存已恢复、跳过、冲突、失败、未尝试和校验异常汇总。引擎整体恢复或校验失败时无法精确区分失败原因，校验异常数量返回未知，不能显示为零异常。失败条目明细有响应数量上限，目前最多 200 条；没有完整逐项成功导出或从失败任务逐文件自动续跑。失败或取消前的输出可能保留，不能推断目标完全未改变。
- 云端发现重建仓库登记、恢复点和其文件索引，不恢复原节点的备份计划、宿主机源路径、调度配置或审计历史。当前页面在原源未登记时会展示逻辑 `source_id`；可按该标识和文件路径选择恢复范围。
- 首次发现需要读取完整选定的加密控制资料以重建索引，然后再分页浏览；不下载全部业务备份，但也不是仅为打开一个文件下载少量目录节点。
- 恢复节点可每分钟在服务端自动检查新提交；锁定或服务停止时暂停。检测变化后更新索引，重复证书不重复下载完整目录或复制旧点索引。自动发现不自动下载业务文件或镜像本地目录。自动发现从可接入账号选择最新可认证的目录提交。离线、权限失败和认证失败的候选会跳过，没有完整逐候选诊断界面；需要结合任务日志与人工恢复手册排查。

## 调度、容量与维护

- 备份支持 Cron、固定间隔、显式时区、重试次数与带宽上限；全局并发是部署配置。重试退避由服务固定计算，当前没有按计划配置退避曲线、错误白名单或每账号并发数量的界面。
- 合并触发已持久化，重启会识别中断任务。它不承诺任意字节级断点续传，也不自动把中断任务恢复为原执行现场；后续重跑与复用取决于 Restic/Rclone。
- 容量以真实查询、整数 Bytes 与事务预留规划。估算仍是保守启发式：修改内容通常按完整逻辑大小加开销，未变化估算依赖大小与时间，而不是预先计算所有内容的云端压缩和去重结果。云端实际容量变化、外部写入和底层配额行为可能使已经通过预览的任务失败。
- 新数据按剩余预算和稳定归属规划，没有复杂的目录局部性优化或自动持续平衡。已有分片所在账号不足时会阻止任务，即使其他账号的总空闲容量足够。新增账号不会自动搬迁旧数据。
- 保留策略已实现全局预览和明确确认后的受控清理，当前没有自动定时清理任务。安全暂停包含挂载变化、文件数量大幅下降、未完成点与连续失败等检查，但不构成对所有异常大量改写或云端冲突的完整检测。
- 支持当前备份库的单账号/批量清空，先提交退役记录再删除所选账号的仓库数据，保留最新目录与连接入口。不是整个 OneDrive 或微软回收站清空；要求所有已验证登记账号在线更新删除记录，失败/中断需要选择原账号组重试。恢复节点只读，离线节点旧缓存需重新发现后更新。详见 [批量清空指南](ACCOUNT_CLEAR.md)。
- 整仓迁移的目标账号必须属于仓库所在计划的存储池，且已验证并启用；迁移保留旧副本；独立旧副本清理会验证当前有效仓库及有效快照引用、提交退役登记，再删除选定旧位置。中断或局部云端失败仍可能留下待清理副本，需要查看状态并重试，不能当作瞬间原子搬迁。
- 网页/API 遇到 Graph 限流会返回稳定错误与适用的 `Retry-After`，云端引擎内部重试依赖 Rclone。没有真实云端限流测试，也没有覆盖所有网页登录授权步骤的自动退避调度；不能宣称已经证明微软限流场景的可靠性。

## 资源与规模边界

- `VP_CACHE_MAX_BYTES`、`VP_LOG_MAX_ROWS` 和维护时间窗口已经实现。缓存检查发生在任务与工作阶段边界，不是磁盘硬配额；引擎运行或大文件暂存期间仍可能暂时超过阈值。服务不会为了达标删除活动缓存，应结合宿主机文件系统配额与空间监控。
- 日志按全局保留数量修剪；批量修剪最多暂时多出 127 行，单行最多 8 KiB。过旧的任务日志可能已经被删除。审计记录、任务实体、失败/预览扫描索引和历史加密控制资料当前没有统一自动生命周期回收。
- 维护窗口控制检查、清理、迁移任务的启动时机；窗口结束后不强行取消已经执行的任务，窗口外启动会明确失败，当前不会自动延期排队到下一窗口。
- 文件扫描与清单写入按批次进行，业务文件索引可分页查询。当前每次控制目录提交流式打包所有有效历史恢复点的完整清单，不是增量目录提交；历史数量增长会增加控制目录体积、上传量与首次发现耗时。旧控制目录也保留，容量需要计入预算。
- 部分实体列表与控制登记仍整体读入内存，目录浏览排序会读取直属条目；极多仓库、恢复点或单目录条目的边界未实测。百万合成 SQLite 行测试不能替代百万真实文件扫描、分配、加密目录打包及云端恢复的资源测试。
- 备份任务的上传量使用 Restic 报告的数据新增统计，云端净增长另行对账；这不是包含协议开销、控制资料、重试和失败传输的精确网络流量计量。

本版不包含需求明确放在后续的业务数据第二副本、其他云提供商、集中多节点管理、细粒度权限、数据库备份集成及系统裸机恢复。正式使用前应按实际文件类型、授权范围、存储配额和恢复目标执行自己的恢复演练。

## Rclone 授权边界

- Rclone 共享应用回调固定 localhost，远程或容器部署不能直接自动回到平台域名。网页提供完整回调地址粘贴入口；首次授权仍需微软登录和用户同意。
- 每个实例按顺序授权，标准授权进程占用内部 53682 端口，有效期 10 分钟。服务重启后未完成授权需重试。
- 标准授权和导入目前仅接入全球区 OneDrive Personal；加密 Rclone 配置需先解密，其他 remote 不执行。共享应用可用性和微软侧限制不由本项目控制。
- 尚未使用真实 OneDrive 账号验收标准授权成功、长期刷新和完整云端备份恢复；当前新增测试报告应与本地引擎验收分别阅读。
