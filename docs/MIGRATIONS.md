# 数据库与迁移

首次启动创建 SQLite schema version 1，启用 WAL、foreign_keys 和 busy_timeout。实体独立表保存单资源 JSON 文档与乐观版本，文件清单、稳定归属、容量预留、日志、幂等请求使用独立索引表。它不是单个 JSON 状态文件。

连接参数通过 DSN 对每次新建连接设置：`busy_timeout=10000`、`foreign_keys=1`、`journal_mode=WAL`、`synchronous=NORMAL`。NORMAL 保持数据库一致性，系统崩溃或断电时最近事务仍可能丢失，不能替代云端提交记录与状态备份。审计 ID 保留时间前缀并增加随机后缀，客户端应将其视为不透明字符串；审计列表仍按更新时间排序。

`schema_migrations` 记录已应用的版本。当前为 v3；新增版本必须使用显式事务迁移，并在迁移前备份状态目录。应用索引可由认证云端控制目录重建，SQLite 并不是异机恢复的唯一依据。

v2 为 Telegram 通知增加 `notification_outbox` 和 `notification_incidents`，建表、索引与版本记录在同一事务中完成，原有账号和备份数据保留。通知默认关闭，配置与待发送消息使用原节点密钥加密，独立于云端控制目录。升级前停机备份完整 state 目录；保留 `node-key`，否则原有 OAuth 与 Telegram 凭据无法解密。

v3 将 `file_entries` 的仓库索引替换为 `(run_id,repo_id,source_id,path)`，并移除与主键重复的树索引。新索引创建、旧索引删除与版本记录在同一事务中完成，可重复启动；现有文件清单、稳定归属、容量预留不变。首次升级需为已有清单建立新索引，耗时和临时空间取决于数据量。

文件清单按引用保留：未删除恢复点的 `run_id`、活动任务，以及正在发布的导入索引均受保护。失败、取消与预览运行结束后清理无引用清单；历史清理在恢复点已标记删除后回收清单，即使物理 prune 仍需重试也不会保留不可浏览的清单。启动时异步补扫旧的中断、孤立清单和非活动任务的快照校验行，每批最多删除 5000 行。清理失败记录日志或审计，不覆盖原任务结果，下次启动再次清扫；清理不改变稳定归属和容量预留。

排他节点文件锁禁止两个进程同时打开同一状态目录。重启后进行中任务标记 interrupted；未完整发布的恢复点不能因发现某个快照而成为完整点。原节点损坏时，使用新目录导入恢复包，重新授权账号并重建索引，不拷贝原数据库。

整仓迁移保留仓库逻辑 ID，复制和验证目标后才提交新的物理位置。原位置保留供观察与回退；源副本清理须作为独立明确的风险操作，不能先删再复制。

## Rclone 授权凭据兼容

无需新增 SQLite 表。节点加密凭据从仅保存 OAuth Token 扩展为 Token、应用来源、刷新设置与授权版本。读取旧 Token 格式时按原实例自定义 OAuth 配置兼容；首次刷新或重新授权后写入新格式。导入与重新授权在事务中同时更新账号状态和凭据，旧任务配置携带授权版本，无法覆盖后续的新授权。新增标准授权和导入账号不依赖全局客户端配置。

升级前仍应完整备份停机后的 state。旧版本不能读取新凭据格式；降级时应恢复对应旧状态备份或重新授权，不应直接继续使用已升级的凭据文件。恢复包格式不变，账号凭据仍不包含在恢复包中。
